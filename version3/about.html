Source, build, deploy

Three stages now, where there used to be one.

What happens on push

GitHub Actions checks out the repo, sees package.json, runs npm install and then npm run build. Vite writes the result to dist/. Azure uploads that folder — never your source files.

Which means a build that fails is a deploy that never happens. The previous version stays live. That's a feature.

Why the filenames have hashes

Vite names the output index-B3kQ9x1a.js, where the suffix is derived from the file's contents. Change one character of source and the name changes. That lets the CDN cache these files effectively forever, because a new deploy produces new names rather than new contents at the same name — and no user ever gets a stale mix of old and new code.

Why staticwebapp.config.json moved

It now lives in public/. Vite copies everything in that folder to the root of dist/ untouched, which is exactly where Azure looks for it. Leave it at the repo root and it never reaches the output — which is the single most common reason routing rules silently stop working after adding a build step.
